🔄 标准开发流程

每个模块都遵循相同的六阶段流水线，形成可复制的高效开发范式。

1 需求分析与素材准备
📖 教材研读 → 素材整合 → 知识点拆解

阅读教材对应章节（DOCX/PPT），提取核心概念、算法步骤、示例数据。使用 RAG 检索补充网络资料，生成结构化学习素材 Markdown 文件。确定模块配色方案和模拟器演示数据。

教材 DOCX/PPT RAG 知识检索 xxx_learning_materials.md 确定配色变量
2 主学习页开发
🎮 六标签页架构：导读 + 模拟器 + 基本操作 + 理论知识 + 练习题 + 实训入口

单文件 HTML 内联全部 CSS/JS。模拟器使用纯 SVG+DOM API 实现（避免外部依赖），支持单步执行、自动播放、速度调节。理论知识页包含代码展示、图示、术语解释。练习题含自动批改与解析。

xxx-app/index.html SVG 模拟器引擎 Tab 切换组件 练习题自动批改
3 实训页面开发
💻 纯实验指导书风格：详细步骤 + 完整 Java 源码 + 逐行深度解析

严格遵循「实验指导书」规范——禁止仿真平台/代码填空框/JS 验证按钮。每个任务包含：实验目的→测试数据→算法思想→手动模拟→完整源码（与教材一致）→逐行深度解析（三列网格：行号 | 代码 | 解析+标签）→预期输出→性能分析→操作步骤。

xxx-training-app/index.html analysis-block 三列网格 代码标签分类系统 core/logic/trap/api/note/data
4 导航联调与风格统一
🔗 全站导航规范 + 配色体系 + 响应式适配

主学习页导航：导读|模拟器|基本操作|理论|练习|实训(外链)|返回首页。实训页导航：实训(current高亮)|其他tab回链主学习页?tab=xxx。统一卡片样式、进度条、状态指示灯动画。移动端响应式断点统一 ≤860px。

全站导航规范 URL 参数 tab 跳转 移动端堆叠布局
5 首页更新 + 本地预览验证
🏠 更新首页卡片 → 本地 HTTP Server 预览 → 功能验收

首页添加新模块卡片（学习卡 + 实训卡成对），更新统计数字。启动本地服务器（python server.js 或 VS Code Live Server），逐一测试所有标签页功能：模拟器单步/自动、练习题批改、链接跳转、移动端适配。

index.html 卡片更新 Grid 两列布局 本地 HTTP 预览 全功能验收清单
6 Git 提交 + Deploy 脚本推送
🚀 git commit → python deploy.py → GitHub Pages 在线

使用自定义 deploy.py 脚本（已迭代至 v1.7）一键部署到 GitHub Pages。脚本自动处理文件上传，无需手动操作 GitHub 界面。每次提交附上有意义的 commit message 记录变更内容。

git add/commit/push deploy.py 自动部署 GitHub Pages CDN 在线即时访问

🏗️

单文件架构 > 多文件工程化

每个模块就是一个 HTML 文件，CSS/JS 全部内联。看似"不规范"，实则是教育类静态站点的最优解：

  • 零构建工具、零依赖安装、零环境配置
  • 直接双击即可运行，学生无门槛使用
  • GitHub Pages 原生支持，无需额外 CI/CD
  • 版本管理清晰：一个模块 = 一个文件
  • 协作时互不干扰，合并冲突概率极低
🎨

视觉设计驱动学习动机

深色主题 + 渐变色彩 + 微交互动画不是"花哨"，而是降低认知负荷的关键：

  • 深色背景减少眼睛疲劳（长时间学习场景）
  • 每个模块独立配色（蓝/紫/琥珀/绿），建立心理锚点
  • 动态 orb 背景营造沉浸感，提升"产品品质感"
  • SVG 模拟器比文字描述直观 10 倍以上
  • 单步执行让学生"看到"算法在跑，而非死记硬背
🧪

"仿真平台"不如"实验指导书"

早期尝试过在线代码编辑器+运行验证方案，最终完全废弃，原因深刻：

  • 浏览器端 JS 运行 ≠ Java 真实环境，误导学生
  • 代码填空框限制了思路，变成"猜答案游戏"
  • 教师需要的是完整源码+深度解析，而非在线 IDE
  • 实验指导书风格更符合高校教学大纲要求
  • 逐行解析的三列网格（行号|代码|标签化注释）才是真正的"助学工具"
🔧

SVG 原生渲染优于第三方库

迷宫、队列、查找表、图等可视化全部使用纯 DOM + SVG API实现：

  • D3.js 仅用于复杂树形结构的力导向布局
  • 零外部依赖意味着永远不会有版本冲突
  • 透明 hit-area 技巧解决 SVG hover 问题
  • lastState 全局变量保存帧状态，支持重绘恢复
  • 文件体积小 80%，加载速度更快
📐

先定规范，再动手写代码

项目中期才确立的全站规范文档是效率倍增器：

  • 导航顺序/命名/高亮规则统一后，新模块开发时间缩短 50%
  • CSS 变量体系（--accent/--accent2/--success）全局复用
  • 实训页面的 analysis-block 格式一次定义，全项目通用
  • 代码标签分类（core/logic/trap/api/note/data）形成标准词汇表
  • deploy.py 脚本随新模块扩展，版本号记录演进

AI 协作模式：Craft + Ask 双态切换

WorkBuddy 的三种工作模式在实际开发中的运用策略：

  • Craft 模式：写代码、重构、调试——占 70% 时间
  • Plan 模式：架构决策、方案选型、多步骤任务规划
  • Ask 模式：技术调研、API 文档查阅、快速问答
  • 关键策略："说需求不给细节" → 让 AI 自主判断最优路径
  • 遇到问题直接说"重写"，AI 全新实现比修改更快更干净
